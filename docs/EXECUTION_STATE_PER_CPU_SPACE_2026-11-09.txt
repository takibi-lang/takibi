Measured physical costs
-----------------------
The real current/stack publishers run on the boot CPU before peer dispatch,
with live boot PID0 and protocol tracing inactive. Each timed pair takes the
run lock and a CPU region; the matched empty envelope does the same without
publication. A pair performs one current plus one stack publish, including
their actual pooled PID lookups. Three samples each contain 4096 pairs;
reported values are separate finite minima, not bounds.

Counter frequency: 54000000 Hz.
Empty envelope: 17900 ticks / 4096 = 80.928096 ns/pair.
Published pair: 54516 ticks / 4096 = 246.473524 ns/pair.
Increment: (54516 - 17900) ticks / 4096 = 165.545428 ns/pair.
The calculation uses raw ticks before rounding. These are not independent
per-publisher measurements and not a whole context-switch latency.

Real paths have different publication counts. An idle successor commit has
handle/live current publications (2); a running successor replacement has
one current publication. EL0 IRQ departure has one stack publication;
arrival after departure has stack handle/live publications (2), whereas a
direct physical replacement with the old stack still live has 3. Exit to
idle clears current then stack (1 each). Live=false publication skips the
pooled lookup; handle/live setters while already live may each look it up.
The measured pair is not multiplied into a universal handoff estimate.

The same 16-iteration busy pair (16000000 steps/iteration) completed with
identical PIDs/checksums: elapsed counter ticks 15582052 -> 15582309,
0.288556519 -> 0.288561278 seconds. Per-CPU records retain placement and
background work: CPU0 context switches 0 -> 0, CPU1 39 -> 41; background
blocks/syscalls differ. This one-run result is not statistical nonregression.

The existing 256 KiB move workload alternates CPUs 2/3. Median cold/warm
cycles are 79338/29755 baseline and 79410.5/29822.5 candidate; median
cold-minus-warm 49537 -> 49582.5 (+0.092% approximately), over 7/8 versus
8/8 clean rounds. Each version's cold and warm passes retire equal work,
but clean instruction counts differ across versions (62165 -> 62628).
Intervals begin after affinity migration: they measure post-move cache/TLB
refill and their measurement envelope, not migration-path instructions or
publication latency. No causal or general performance guarantee follows.

The separate IRQ-off sampler measured 11.5 -> 9.6 ns/mask pair, least of
14 samples of 4096 pairs. Judged classes pass their existing thresholds;
raw maximum includes the deliberately masked peer-sleep fixture. Neither
its sample nor the busy-pair/move sample establishes a worst-case bound.

allocations (the independently recorded #1485 defect). Local corrected
measurement accepts hexadecimal and decimal immediates from the exact
llvm-objdump-19 -d --no-show-raw-insn inputs and retained object hashes.
All four preserved baseline objects were measured directly, including debug.
Both targets, baseline and candidate:
  scheduler frame: 3184 production / 3312 debug bytes;
  ext2_update_regular_file: 2528 production / 2640 debug bytes.
The old 3088/3216 and 2432/2544 reports each missed 96 bytes. The shared
checker and budgets are unchanged by this feature; no new parent-frame
increase is claimed from the corrected comparison.

Production publishers each have 32-byte frames, not zero. Debug helpers:
probe wrapper 48, held probe 64, live setter 32, publisher 64, PID-of-handle
48, PID-of-slot 32, scalar snapshot 128 and pool-lock entry 32 bytes.
A compiled-callgraph-confirmed PID0 path sums listed frames to 3760 bytes;
the cost-probe path through its logger/sample sums 3840 bytes. Pool-lock
callees, other branches, interrupts and generated frames are excluded.
These partial sums are not whole-callgraph or 16 KiB stack bounds. Extracting
fixture scopes restored the prior parent's size; it did not remove helper
call costs or prove that 80 bytes disappeared from every live callpath.
