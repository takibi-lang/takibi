# RPi5 provisioning image, LZ4-compressed (#1218, 2026-10-30)

GitHub issue #1218: every RPi5 lane loaded the 6 MiB ext2 image the board
writes to its USB stick over SWD, about 34 s of a 37 s load. The kernel now
embeds a zero-block-elided, LZ4-compressed container
(`scripts/lz4_image.py`, expanded per 64-block chunk by
`kernel/lib/lz4_image.tkb` over `kernel/lib/lz4.tkb`).

## Linked kernels

`python3 scripts/space_delta.py origin/main`:

```
| | qemu base | qemu change | rpi5 base | rpi5 change |
| text | 746376 | 746376 | 800760 | 4110360 |
| data | 5000 | 5000 | 6297776 | 6312 |
| bss | 1490944 | 1490944 | 1699840 | 1765376 |
| usable_ram_start | 0x40228000 | 0x40228000 | 0xa68000 | 0x7a0000 |
data/BSS symbols changed:
  rpi5: usb_provision_block 1024 -> None
  rpi5: usb_provision_expanded None -> 65536
  rpi5: usb_provision_image 6291456 -> None
```

The container (3308152 B, ext2.img and ext2-shell.img padded to one length)
moved from `.data` to `.rodata`, so it counts as text; the codec and the
expansion add about 1.4 KiB of code. BSS grows by the 64 KiB chunk buffer,
less the 1 KiB block buffer it replaces. QEMU carries no image and is
unchanged. The RPi5 image end moves down, so the allocator gains 712 pages
(`allocator_pages` 258456 -> 259168 in the boot view).

## Board

| | bytes loaded | load time | rate |
|---|---:|---:|---:|
| before (main, last board run) | 7098536 | 37.68 s | 184.0 KiB/s |
| after (`make kernelcheck-rpi5`, PASS) | 4116672 | 21.67 s | 185.5 KiB/s |

16.0 s less on every RPi5 lane load. Provisioning, now including the
expansion, reported `write10_commands=96 elapsed_ms=269` (146-184 ms in the
#790 review's runs before it); the verify pass expands the image a second
time, about 80 ms between the two log lines.

## Assessment

Adopted. The compression ratio (6291456 -> 3308152) is the greedy host
encoder's on an image that is mostly executables; a stronger encoder would
shrink it further, and the provision-on-hash-mismatch option in the issue
would remove the image from the usual load entirely. Neither is needed now.
