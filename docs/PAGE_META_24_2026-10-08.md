# PageMeta 32 -> 24 bytes per managed page, 2026-10-08

Workload: the standard production QEMU/RPi5 linked images and the QEMU main
lane boot, before (dda17a75) and after narrowing `PageMeta.map_refcount` from
`usize` to `u32` in `kernel/mm/page.tkb` (GitHub issue #389).

## Layout

| | before | after |
|---|---|---|
| `occupied`, `owner`, `map_refcount` | 1 + 1 + 6 padding + 8 | 1 + 1 + 2 padding + 4 |
| `next_free`, `physical` | 8 + 8 | 8 + 8 |
| `sizeof(PageMeta)` | 32 | 24 (held by `static_assert(sizeof(PageMeta) <= 24)`) |

Retains stop at `PAGE_MAP_REF_CEILING` (u32 maximum) as well as at the
caller's live address-space count, so the narrower field cannot wrap.

## Runtime metadata (one `PageMeta` per page of discovered RAM)

| board | managed pages | before | after | saved |
|---|---|---|---|---|
| QEMU virt, 1 GiB | 261560 | 8369920 B | 6277440 B | 2092480 B (511 pages) |
| RPi5, 1 GiB (bootloader view) | 259312 | 8297984 B | 6223488 B | 2074496 B (506 pages) |
| 8 GiB board (projected, 2097152 pages) | | 64 MiB | 48 MiB | 16 MiB |

Metadata is 0.59 percent of managed memory, down from 0.78 percent.

## Linked image (llvm-size -A, bytes)

| image | section | before | after | delta |
|---|---|---|---|---|
| QEMU | .bss | 1243952 | 1227568 | -16384 |
| QEMU | .text | 553920 | 553952 | +32 |
| RPi5 | .bss | 1283232 | 1266848 | -16384 |
| RPi5 | .text | 560120 | 560184 | +64 |

The .bss saving is the bootstrap `[PageMeta; 2048]`. On RPi5 it moves the
allocator start back across a 32 KiB boundary: `allocator_pages` 259304 ->
259312.

## Decisions on #389's other items

| item | decision | reason |
|---|---|---|
| fold `occupied`/`in_run` into a bitmap | declined | `in_run` is gone; `occupied` and `owner` already sit in the first word's padding, so a bitmap saves nothing |
| merge `next_free` into `PageMeta` | already done | the current struct holds it |
| two-level (sparse) metadata | declined | the cost scaled with a compile-time ceiling when #389 was filed; it now scales with discovered RAM, which is the asymptotic case sparse metadata was meant to fix |
| derive `physical` (24 -> 16 bytes) | split to #718 | trades a lookup per physical-address query for space; waits for an RPi5 time measurement method |
