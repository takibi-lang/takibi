# Equal-workload pool space replay

This is a space experiment against actual Takibi, Linux SLUB and FreeBSD UMA,
not a comparison of kernel HTTP/process/FD service workloads. The nine object
sizes in `workload.tsv` come from the maintained AArch64 kernel baseline on
2026-10-05. Every payload has alignment 8. No payload is read or initialized;
this isolates allocator storage. The workload does not reproduce pins,
concurrency, handle lookup, network traffic, or allocator throughput.

For each allocator, create a fresh private pool/cache/zone for each object
size and each count (32, then 128). Allocate ascending IDs, free ascending even
IDs, refill ascending even IDs, then free all IDs in reverse order. Sample
`empty`, `full`, `half`, `refill`, and `free` in that order. Each case is
independent; sums below are a sum of independent observations, not a single
simultaneous OS snapshot. The final sample is immediate, before allocator
teardown, background draining, or memory pressure. Every allocator is then
destroyed/reclaimed. Retention differences are policy observations, not leaks.

`linux_user/pool_space_replay` uses the actual built-in RegionPool and maintained
intrusive allocator with the existing native fake page provider. It mirrors
production chunk sizes and empty-chunk retention. Its byte-array payloads
carry the measured production object sizes; it is not a semantic process/FD
implementation. Takibi runs single-threaded on AMD64. The OS guests run AMD64
with two vCPUs and 1 GiB RAM under QEMU 8.2.2 TCG; their serial allocation
work is bound to CPU 0, with an idle second CPU. OS per-CPU metadata is charged
for both CPUs. Timing and physical cache behavior are outside the verdict.

## Accounting boundary

`bytes` charges all private object slabs/chunks, including unused slots,
in-slab metadata, alignment, and tail slack. Takibi has eight bytes of
state/generation per slot (also pins in built-in pools), a 24-byte built-in
header or 128-byte intrusive header reservation. Linux overlays its free
pointer in the payload; FreeBSD puts its bitmap/header in these slab pages
for these sizes. No FreeBSD off-page slab header or hash was needed here.

`aux_bytes` separately charges private pool/cache/zone descriptors and the
observed attached allocation machinery. Takibi charges its 104-byte intrusive
body or 16-byte built-in body. SLUB charges descriptor/node object storage
using `ksize`, logical per-CPU cache storage, and the random-freelist table.
UMA charges rounded zone/keg allocations, per-CPU counters, buckets rounded
through the release's bucket size classes, and hash/off-page storage when
present. UMA zone storage already includes its per-CPU caches and domain
records. Its public current-allocation counter must equal the replay's live
count. Linux's debug accounting counters observe slab count and capacity;
normal allocation/free operations determine the live count. No order fallback
occurred: the parser checks SLUB capacity against observed slab order/stride.

`charged_bytes = bytes + aux_bytes`. This is a stated allocation boundary,
not total physical RAM, RSS, or a full accounting of each OS. The shared
metadata allocator's unused slab capacity, per-CPU allocator placement slack,
page/buddy allocator structures, Linux `struct page`, FreeBSD `vm_page`,
name strings, sysfs/sysctl registration, code, stack, handle arrays, and the
Takibi stand-in page-provider arena are excluded. Metadata allocation units
are rounded where the driver observes or derives them; shared parent pages
are not charged. Allocator safety guarantees are not equivalent: neither OS
cache adds Takibi's stale-handle generation check. No density result implies
that this guarantee can be removed safely.

## Reproduce the native replay and aggregation

From the repository root:

```sh
make linux_user/pool_space_replay/pool_space_replay.exe
linux_user/pool_space_replay/pool_space_replay.exe > /tmp/takibi-replay.txt
python3 scripts/measure_pool_replay.py --takibi /tmp/takibi-replay.txt \
  --slub /tmp/slub-replay.txt --uma /tmp/uma-replay.txt
```

The generated Takibi specializations have a tracked hand-written template in
`linux_user/pool_space_replay/region_replay.tkb.in`. Generated content includes
only derived payload types and concrete template instantiations. The native
fixture is part of `make linuxcheck`, uses `--forbid-trap`, and must return the
page-provider use count to zero after all 18 cases. The maintained capture
controls require every sample, matching sizes/lifetimes, complete successful
teardown, and consistent numeric accounting. External OS guests are an
explicit measurement step; the aggregate does not download or boot them.

`captures/*.txt` preserves the observation rows and completion markers from
the 2026-10-05 experiment. `comparison.tsv` is regenerated by the command
above using the three primary captures. Repeat captures record a second run.
This is dated evidence, not a claim about future kernel versions.

## Linux guest

Use Alpine 3.22.6 AMD64 with `linux-virt` and `linux-virt-dev` 6.12.111-r0,
gcc 14.2, and matching Linux v6.12.111 source. Packages came from
`https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64/`.
SHA256 of the downloaded kernel APK is
`9cbdae673871dd67cddb607c4a7b4989cbc3374a537c946f4e559fe483fb34f1`,
and of the development APK is
`c13626d51a827e69586c307d1865a537bc62ae77a915fb855432939f344f7b1c`.
Matching private definitions come from `mm/slab.h` and `mm/slub.c` in the
[kernel stable source](https://github.com/gregkh/linux/tree/v6.12.111).
Their SHA256 values are respectively
`023ae621ca5aac702257bdd23bcf84269ccae03f0b1316f9818114d5618f6b99`
and `e7af8e743f747c163e29b5936324cbcffeefc424c9628c7683b558dd588a2264`.

The shipped kernel has SLUB, NUMA, SMP, SLUB_CPU_PARTIAL, SLUB_DEBUG and
SLAB_FREELIST_RANDOM enabled; SLUB_DEBUG_ON, SLUB_STATS, KASAN,
SLAB_FREELIST_HARDENED and MEM_ALLOC_PROFILING are disabled. Each cache uses
alignment 8, SLAB_NO_MERGE, no constructor and no SLAB_ACCOUNT. Thus it is
private, its normal in-payload freelist remains active, and no per-object
memcg extension is charged. Allocation tracing/debug options must stay off.
The private observer is tied to this release/configuration; do not silently
reuse its layouts on another kernel.

Prepare a module directory in the disposable guest (replace paths with the
matching source and build directory):

```sh
python3 scripts/prepare_pool_replay_linux.py /path/to/linux-6.12.111 /tmp/slub-build
python3 scripts/generate_pool_space_replay.py --c-header /tmp/slub-build/replay-workload.h
cp kernel/benchmarks/pool_space/linux/linux_module.c /tmp/slub-build/
cp kernel/benchmarks/pool_space/linux/Makefile /tmp/slub-build/
# Inside the guest, with that directory at /replay:
make -C /lib/modules/6.12.111-0-virt/build M=/replay GCC_PLUGINS_CFLAGS= modules
```

The external module build disables GCC plugin flags (the chroot's latent
entropy plugin could not obtain entropy); it does not change the kernel or
allocator policy. Put a static BusyBox at `/bin/busybox`, the tracked `linux/init`
at `/init` (executable), the module at `/linux_module.ko`, and empty `/proc`,
`/sys`, `/dev` directories in a newc initramfs. Boot with:

```sh
qemu-system-x86_64 -m 1024 -smp 2 -kernel /path/to/vmlinuz-virt \
  -initrd /path/to/replay.cpio -append 'console=ttyS0 rdinit=/init panic=1' \
  -nographic -no-reboot > /tmp/slub-replay.txt
```

Load this observation module only in the disposable guest. No host kernel
module is loaded and no guest allocator tuning is applied.

## FreeBSD guest

Use the official FreeBSD 15.0-RELEASE AMD64 BASIC-CLOUDINIT UFS image and
matching `src.txz`, stock GENERIC, clang 19.1.7. Both are available under
`https://download.freebsd.org/releases/`. The image reports
`releng/15.0-n280995-7aedc8de6446`; it has two CPUs, one VM domain and
`vm.debug.uma_multipage_slabs=1`. INVARIANTS is disabled. No update or custom
kernel was installed. Source/image SHA256 was checked against official
MANIFEST/CHECKSUM.SHA256:

- `FreeBSD-15.0-RELEASE-amd64-BASIC-CLOUDINIT-ufs.qcow2.xz`:
  `7b70f210fa737c53c911f6298e5640f19ae692fbf457dd26dae6f1bfd7a709b8`.
- `src.txz`:
  `83c3e8157b6d7afcae57167fda75693bf1e5f581ca149a6ecb2d398b71bdfab0`.

Boot a disposable copy with QEMU TCG, `-m 1024 -smp 2`, a virtio disk/network,
and serial console. Disable first-boot package/update services before running
the measurement. Install the matching `/usr/src` source tree. Generate
`replay-workload.h` with the same command used for Linux, copy it and
`freebsd/{Makefile,freebsd_module.c}` to `/root/replay`, then in the guest:

```sh
cd /root/replay
make
# Clear previous log copies so each sample appears once.
dmesg -c > /tmp/prior-dmesg
kldload ./freebsd_module.ko
status=$?
dmesg
echo module_status=$status
if [ "$status" -eq 0 ]; then kldunload freebsd_module; fi
```

Capture this command's stdout as `/tmp/uma-replay.txt`. The module uses
`uma_zcreate`, `uma_zalloc`, `uma_zfree`, `uma_zdestroy`, and the public
`uma_zone_memory`/`uma_zone_get_cur` observations. Matching `vm/uma_int.h`
is used only to account for private zone/keg/bucket layout. Bucket accounting
matches `bucket_zone_lookup` and `bucket_init` in the release's `vm/uma_core.c`.
No constructor/destructor, zone flags, or custom cache limit is installed.
